Доступ к российским источникам

Использовать существующий общий загрузчик проекта; не создавать личный прокси, параллельный реестр или отдельный загрузчик для каждого агента.

Порядок и команды: общий маршрут ../../registries/autonomous-access.md. Базы по музеям: профильные фонды ../../registries/README.md.

  • Начинать с точного предмета: название, автор/создатель, дата, инвентарный номер. Поиск query.py выбирает фонд, а не ищет произведение внутри него.
  • Пробовать точную карточку через access.py --url ... --contains ... --require-exact. Общая страница фонда и HTTP 200 сами по себе не подтверждают получение предмета.
  • При отказе выполнить предметный поиск доступным агенту веб-инструментом. access.py --source ... --query ... --discover подготавливает запросы site:, но не выполняет поиск. Если веб-инструмента нет, использовать доступный каталог или профильные фонды; не обещать наличие инструмента другого агента.
  • Проверять «Артефакт» и сайт музея-хранителя: карточка того же предмета может быть доступна независимо от Госкаталога. Сверить реквизиты; не подменять предмет похожим и не считать описание доступом к оригиналу изображения/книги.
  • Индекс поиска — только метаданные с датой проверки; bridge_snapshot — историческая копия с проверенным SHA. Ни то ни другое не означает живой доступ к исходному сайту. Материал из другого фонда обозначать отдельно.
  • Прочитать полученный файл, проверить предмет, полноту, разрешение и права. Сохранить report.json и файл с SHA. Не повышать file_confirmed для всего фонда после одной карточки. Не объявлять доступ из РФ без проверенного узла РФ.
  • После ограниченного прямого повтора перейти к следующему маршруту. Не обходить капчу, платный/закрытый доступ; не арендовать сервер и не запускать служебных ботов под видом чтения источника. Недоступность одного уникального документа фиксировать адресно, продолжая независимые части работы.

Проверенная карточка для проверки установки и порядок переноса в другой контейнер даны в общем маршруте. Успешная проверка одного агента не доказывает установку у других.

Самостоятельный доступ для всех музейных агентов

Один runtime — access.py, одна база — sources.json, один навык — docs/skills/museum-source-access/SKILL.md. Работает из любого текущего каталога, Python 3 со стандартной библиотекой; дополнительные сертификаты берутся из certificates/ с проверкой SHA. Браузер/поиск подключаются средствами конкретного агента и не являются обязательной зависимостью прямой загрузки.

Предмет, затем маршрут

  1. Выбрать профильный фонд через query.py --museum <профиль>. Это поиск фондов, не предметов. Если точный URL известен, сразу загружать его.
  2. Получить точный документ с ожидаемым фрагментом. Использовать отдельную папку результата на задачу, чтобы агенты не перезаписывали файлы друг друга.
  3. При отказе найти ту же карточку через веб-поиск, «Артефакт» или музей-хранитель. Сопоставить название, автора, дату, инвентарный номер. Если это другой предмет, отметить альтернативу и не выдавать её за исходный документ.
  4. Если точный оригинал остаётся недоступен, использовать индексированные сведения только как сведения из индекса; исторические файлы моста — только как снимки. Уникальный недоступный скан остаётся отдельной зависимостью, остальная работа идёт.
RC_PROJECT_ROOT="${RC_PROJECT_ROOT:-$HOME/projects/russian-civilization}"
/usr/bin/python3 "$RC_PROJECT_ROOT/docs/registries/access.py" \
  --url https://ar.culture.ru/ru/subject/burlaki-na-volge-1 \
  --contains 'Бурлаки на Волге' --require-exact --out-dir /tmp/source-access-sample

/usr/bin/python3 "$RC_PROJECT_ROOT/docs/registries/access.py" \
  --source goskatalog --query 'название предмета инвентарный номер' \
  --discover --out-dir /tmp/source-discovery

Второй вызов только составляет план: status=discovery_only, artifacts=[]. Агент сам исполняет предложенные запросы своим доступным поисковым инструментом, открывает найденную точную карточку и повторяет первый вызов с её URL. Нет поискового инструмента — использовать прямые каталоги и известные фонды, зафиксировав not_searched; не имитировать поиск из памяти.

--require-exact требует непустой --contains; код 0 означает полученное тело исходного URL с ожидаемым фрагментом. Перенаправление на другой URL, другая коллекция или исторический снимок дают код 2 в этом режиме. Каноническое перенаправление можно открыть, проверить и запросить его конечный адрес явно. Это машинная проверка адреса и текста, не экспертная атрибуция или разрешение публиковать изображение. HTML-карточка, полный текст, скан и оригинал изображения проверяются раздельно. Без --require-exact сохранено прежнее поведение: код 0 может означать альтернативный материал; читать relation в отчёте.

Что реально подтверждено

23.09.2026 напрямую скачана указанная карточка «Артефакта» с ожидаемым текстом. Это одна проверенная карточка, не проверка всего каталога или российского IP. Поиск показал метаданные карточек ГИМ и НЭБ; их прямая загрузка не подтверждена. Действующий российский мост не прислал heartbeat. Развёртывание облака не выполнено. Не записывать сайты целиком как недоступные по одному адресу; не записывать их целиком как доступные по одной удачной карточке. Повторять адресную проверку при использовании материала в другой задаче.

Установка в контейнер каждого агента

Проверенный общий runtime и навык должны находиться в клоне проекта. Не копировать один access.py: нужны реестры, transport.py, сертификаты и связанные описания. После получения версии проекта выполнить в каждом контейнере от его пользователя:

/usr/bin/python3 "$RC_PROJECT_ROOT/docs/registries/install-source-skill.py" \
  --apply --report /tmp/source-skill-install.json
/usr/bin/python3 "$RC_PROJECT_ROOT/docs/registries/install-source-skill.py" \
  --check --report /tmp/source-skill-check.json

Установщик добавляет общий навык в .codex/skills и .claude/skills текущего пользователя, а существующим музейным навыкам добавляет небольшой блок маршрута. Для другого загрузчика указать его каталог через --skills-dir. Остальной текст навыков сохраняется. Он не меняет модели, секреты, конфигурацию ботов, PAUSED или чужие домашние каталоги. Повторный запуск не дублирует блоки. Сначала допустим --check: отсутствующая установка возвращает код 2 и список различий.

Затем выполнить живую загрузку карточки из первого примера. Сохранить оба отчёта отдельно для каждого контейнера. Установка подтверждается SHA runtime и навыка, сеть — конкретным report.json. До получения этих квитанций статус других контейнеров — «не проверено», даже если проект доступен всем агентам.
